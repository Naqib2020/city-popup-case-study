# City Popup

Public-safe case study for a private organization platform.

## Overview

City Popup is a multi-domain marketplace and e-commerce platform with a public website, Laravel backend/admin system, and Flutter mobile app. It supports regional/domain experiences across `.de`, `.ae`, and `.nl`, plus public product discovery, shops/domains, authentication, cart and order workflows, reviews, support, notifications, localization, and payment-related flows.

## My Role

Worked across the website experience, backend APIs, admin/backend modules, Flutter application structure, authenticated workflows, multi-domain/shop behavior, cart and order features, and integration-heavy platform modules.

## Platform Modules

- Public product, category, shop, banner, blog, legal page, and home APIs
- Multi-domain website experiences for `.de`, `.ae`, and `.nl`
- Authentication, social auth, password reset, profile, and role-based access
- Product details, favorites, reviews, cart, orders, invoices, and re-order flows
- Support tickets and ticket messages
- Domain and shop selection for the Flutter app
- Payment gateway flows and payment callbacks
- Flutter mobile app with domain selection, local cart storage, FCM, localization, downloads, and dynamic theming

## Technology

- Laravel 11, PHP 8.2, Sanctum
- Modular Laravel structure, permissions, QR/barcode/PDF/Excel packages
- Stripe, Razorpay, Paystack, MessageBird/Twilio/Vonage-style communication packages
- Flutter, Dart, Riverpod, Hive, Dio, Firebase Messaging, Pusher channels

## Technical Highlights

- Built a broad API surface for marketplace, catalog, cart, order, support, content, and account flows.
- Connected website and Flutter startup logic to domain selection, stored auth tokens, localization, theme state, and notifications.
- Supported product scanning, payment-related flows, invoice/download behavior, and realtime channels.
- Added admin/backend capabilities for commercial marketplace operations.

## Privacy

The source code is private. This case study excludes private repository details, customer data, order/payment records, admin screens, internal URLs, credentials, and unsupported business metrics.
